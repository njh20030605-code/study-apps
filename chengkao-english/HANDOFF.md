## 一句话
面向**零基础/基础薄弱**成人考生的网页版英语私教（备考成考专升本英语，满分150，目标90+，考试约 2026-10-17）。纯 HTML/CSS/原生JS，双击 `index.html` 即用，离线可用；AI 功能走 **B.AI 中转**。核心理念：**让用户真正学懂→学精→学会**，不是刷题量。

### 🔴 解锁死锁修复（2026-08-03，重要，别改回去）
**旧 bug**：`chapterPassed` 只有一条标准——「做够 min(5,总数) 题 且 一次性通关率≥70%」，而通关率的分母是**全历史第一印象**，错过的题只能靠"连对2次翻案"洗白。实测（真实 recordAnswer + 虚拟日历）：正确率 40% → **永久锁死在第1章**（290天0章、全程只见过 10/427 题）；55% → 锁死在第21章。最需要帮助的零基础用户被彻底挡在门外。
**根因之二**：`buildDailyList` 里本章题只按 `effLevel`(=题目**难度**，不是做过次数) 排序 → 每天都是同几道，本章其余题永远不出现（卡章时42题只做过18题）。
**修法**：
1. `buildDailyList` 改用 `orderForPractice`（没做过的排最前）→ 保证覆盖全章。
2. `chapterPassed` 改为**四通道**，任一满足即解锁：A 真掌握(原标准) / B 最近≥8次正确率≥70%（"现在会了"，摆脱烂开局）/ C 覆盖够且最近≥12次≥55% / D **防死锁兜底**：覆盖够 + 本章累计练习≥40次 → 放行并 `markWeakChapter`。
3. 新增近况追踪：`STATE.progress.recent{章号:[最近20次对错]}` / `chAtt{章号:累计次数}` / `weakCh[]`，在 `recordAnswer` 里写入（靠 `chapterOfQuestion` 反查章）。
4. 薄弱章**固定占每日 ~2 成名额**回访（⚠️ 必须固定名额，放在"本章题不够才补"的分支里会被永远挤掉＝等于没回访），练顺了 `clearWeakChapter` 自动摘标记；今日清单底部显示薄弱章提示。
**修复后实测**：85%→28天通关/薄弱0章、70%→33天/0章、55%→70天/0章、40%→176天/薄弱9章、30%→196天/24章，**全部无死锁**，题目覆盖从 52 题升到 393-412 题。强者的严格性未被牺牲（70%以上仍走 A/B 通道，零兜底）。

### 🔴🔴 boot 竞态：首屏永远走不到冲刺分支（2026-09-12 修，最隐蔽的一个）
**症状**：用户打开 localhost:8899 首屏看到 **7 件任务、带「路线」和「完形填空」**，而这些是冲刺模式明确排除的。手动再 `go("today")` 又完全正常 —— 所以我测了好多轮都没撞上（我每次都是加载完再手动跳转）。

**根因**：`ui.js` 末尾是
```js
tryAutoRestore().then((when) => { boot(); ... });
```
而 `tryAutoRestore()` 在「localStorage 已有存档」时是 **`return Promise.resolve(null)`——同步就 resolve 了**。
于是 `.then(boot)` 在 **ui.js 刚执行完的那个微任务检查点**就跑掉了，
而排在 ui.js 后面的 `collocations.js` / `sprint.js` **还没执行**。
`buildDailyPlan` 里的 `typeof sprintTasks === "function"` 为假 → 冲刺分支被跳过 → 掉回旧的「学习路线」清单。

**修法**：`boot` 改成等 `DOMContentLoaded`（它在**全部同步脚本执行完之后**才触发）：
```js
function startApp(){ tryAutoRestore().then(...) }
if (document.readyState === "loading") document.addEventListener("DOMContentLoaded", startApp);
else startApp();
```

⚠️ **教训：这个 bug 从 2026-09-10 加 sprint.js 那天就在，一直没发现，因为我验证时总是「加载完再手动 go()」。
以后验证首屏行为，必须刷新后直接读 DOM，不能先手动跳转。**
⚠️ 同理，任何「ui.js 之后加载的脚本」提供的函数，都不能被 boot 路径同步依赖 —— 要么前置加载，要么像现在这样等 DOMContentLoaded。

### 🔴 模考「看不见原文」修复（2026-09-09，别改回去）
**用户报的现象**：模拟考试补全对话答题 UI 有 bug。
**实际是三个叠在一起的坑**：
1. `renderMockQuestions` 里 `showP = q.passage && q.passage !== 上一题的passage` —— 换题是**整页重绘**，判「跟上一题同一篇就不渲染」等于第 2 题起原文直接消失。补全对话只剩一句「(57) 处应填：」+ 四个选项，题根本没法做；阅读、完形一样中招；答题卡跳着做更明显（只有第 1 题看得见）。
2. **同一篇下面往往只有第一题挂了 `passage` 字段**（模拟卷二整卷的完形 15 题、5 篇阅读、补全对话全是这么录的：`withP=1 / tot=15`）。所以就算修了第 1 点，直接读 `q.passage` 照样拿到 undefined。→ core.js 新增 `PASSAGE_BY_PID` + **`passageOf(q)`**，取原文一律走它，别再写 `q.passage`。
3. 随机拼卷的补全对话是 `pick(pool, 5)` —— 真卷上补全对话是**一整段对话挖 5 个空**，随机抽出来是「A卷的(56)」+ 几道单句问答 +「B卷的(56)」混成一坨，空号跟原文对不上。→ 改成先找题数够的整段对话（`groupByPassage`），没有才退回单句。
**顺手改掉的 UI 设计问题**：
- 选中的选项以前复用 `.opt.right`（绿＝正确），考场上一点就变绿＝**假反馈**。新增中性的 `.opt.chosen`。
